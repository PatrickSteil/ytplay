# Two decks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ytplay owns the queue and plays through two mpv "decks", so the next song is ready before the current one ends; then add a queue sort by BPM.

**Architecture:** `internal/player` becomes the engine: a pure `queue` (URLs plus a position) and two decks (`mpv.Client`s that each play one file at a time). The player re-emits events in the shapes the UI already consumes, so `internal/ui` keeps its contract. Preload loads the next song paused on the idle deck; handoff unpauses it.

**Tech Stack:** Go 1.26, Bubble Tea, mpv 0.35+ JSON IPC. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-two-decks-design.md`

## Global Constraints

- The UI contract does not change: events are `mpv.Event{Name: "property-change", Property: "playlist" | "playlist-pos" | "pause" | "idle-active"}` and `Name: "end-file", Reason: "error"`; `ui.Actions` keeps its signatures; indexes are positions in the whole list, played songs included (as mpv's playlist).
- `playlist` event data is mpv's shape: `[{"filename": url, "current": bool, "playing": bool}]`; `playlist-pos` data is a number, or `null` when idle.
- Deck sockets are `ytplay-<pid>-a.sock` and `ytplay-<pid>-b.sock` (in `$XDG_RUNTIME_DIR`, else the temp dir).
- `preloadLead` = 15 s; the player polls position every 500 ms.
- If the second deck cannot be started or dies, run with one deck and no preload.
- Sort key is `b` in the queue panel: slowest to fastest, a second press reverses, songs without a BPM go last in their old order. Queued songs are analysed two at a time.
- Gap between two songs after phase 2: under 0.3 s.
- Tests must not need mpv or the network, except tests named `...RealMpv`, which skip when `mpv` is not on PATH.
- `make check` passes at the end of every task. Do not commit unless the user asks.

## Review Focus

- Skip pressed at the instant a song ends: the queue advances exactly once (Task 3, `TestStaleEndFileIsIgnored`).
- The next song is removed, moved, replaced by play-now or the queue is cleared while it is preloaded: the right song plays (Task 5).
- A song that cannot load in the middle of the queue: "Could not play" is shown, the next one plays, and if every song fails the player ends idle instead of looping (Task 3).
- Queue edits at the edges: remove the playing song, move the first or last upcoming song, skip on the last song, queue a song after the queue has finished (Tasks 2, 3).
- Pause: a preloaded deck never starts while the user has paused, and skipping while paused stays paused (Task 5).

### Task 5: preload and handoff

**Files:**
- Create: `internal/player/preload.go`; Modify: `internal/player/player.go`
- Test: `internal/player/preload_test.go`

**Interfaces:**
- Consumes: Task 3 internals. Needs a second `fakeDeck` from a fake `StartDeck`.
- Produces: `const preloadLead = 15 * time.Second`, `const pollEvery = 500 * time.Millisecond`; `func (p *Player) poll(ctx context.Context)` (one check, called by a ticker goroutine started in `New` and stopped by `Close`; tests call it directly).
- Rules: `poll` preloads when a next entry exists, none is preloaded, and `duration - time-pos <= preloadLead`: start deck `"b"` if not started, send `set_property pause yes` then `loadfile <url> replace`, remember `{url, deck, entryID}`. Whenever the entry after the current one changes (remove, swap, play-now, clear, reorder) the preload is dropped (`stop` on the idle deck). Advancing with a matching preload does not reload: `set_property pause <userPaused>` on the preloaded deck, it becomes active, the old deck gets `stop`, events are emitted. A preload that fails (command error or `end-file` error on its deck) is dropped silently; the next advance cold-loads on the active deck.

  - `TestPreloadStartsWithinTheLeadOfTheEnd` (`time-pos` 185, `duration` 200 → deck b receives `set_property pause yes`, `loadfile <next> replace`; with `duration` 300 nothing; a second `poll` does not load again)

  - `TestHandoffUnpausesThePreloadedDeckWithoutReloading` (after `eof` from deck a: deck b gets `set_property pause false`; deck a gets `stop` and no `loadfile`; `playlist-pos` is 1; the next `poll` preloads entry 2 on deck a)
